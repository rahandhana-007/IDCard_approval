Hubungkan ke Supabase

KartuSign memakai database online (Supabase): akun, kunci tanda tangan, antrean pengajuan, dan riwayat tersinkron antar perangkat — user bisa mengajukan dari mana pun, manager menyetujui dari perangkat lain.

Langkah menyiapkan Supabase (gratis):
1. Buat proyek di supabase.com.
2. Buka SQL Editor → jalankan seluruh isi file supabase/schema.sql.
3. Authentication → Providers → Email → matikan Confirm email.
4. Settings → API → salin Project URL dan anon public key ke form ini.
Akun pertama yang dibuat di aplikasi otomatis menjadi manager.

5 Catatan keamanan

Aplikasi berjalan di browser dengan backend Supabase (Auth + Postgres + Row Level Security). Yang dikirim ke server: akun/login, gambar & data kartu pada antrean pengajuan, payload QR hasil, dan blob kunci privat yang sudah terenkripsi AES-256-GCM dengan frasa sandi Anda — server tidak pernah melihat kunci privat dalam bentuk terbuka. Proses kriptografi (pembuatan kunci, hash, tanda tangan, QR) tetap 100% di browser. Untuk produksi skala besar, pertimbangkan HSM / layanan tanda tangan terpusat.

Integritas

Cara kerja

  1. Hubungkan Supabase sekali saja (URL + anon key, lihat panel pengaturan server), lalu buat akun / masuk. Akun pertama otomatis menjadi manager (level 2); manager menambah akun user (level 1) di tab Kunci & Akun. Login & data tersinkron antar perangkat.
  2. (user, dari perangkat mana pun) Upload gambar kartu, isi nama/ID/masa berlaku, lalu Ajukan Approval — pengajuan tersimpan di server dan langsung masuk antrean manager.
  3. (manager) Buat kunci sekali saja di tab Kunci & Akun — kunci privat disimpan terenkripsi frasa sandi di server, sehingga manager dapat menandatangani dari perangkat mana pun.
  4. (manager) Di tab Approval & Tanda Tangan, pilih permintaan dari antrean (atau muat kartu ad-hoc).
  5. Aplikasi menghitung SHA-256(metadata + byte gambar), lalu menandatanganinya dengan kunci privat.
  6. Hasil tanda tangan dikemas jadi QR code dan ditempelkan ke kartu sesuai posisi/ukuran pilihan Anda.
  7. Unduh PNG/JPG atau cetak kartunya; status permintaan berubah menjadi disetujui dan terlihat oleh user.
  8. Petugas memeriksa keaslian di tab Verifikasi: cukup tempel isi QR → hasil KARTU INI ASLI atau TIDAK ASLI. Tanpa kunci publik, tanpa upload gambar.
  9. Agar verifikasi bekerja di perangkat petugas, unduh KartuSign-Verifier.html dari tab Kunci & Keamanan (kunci publik Anda tertanam di dalamnya) dan bagikan file itu.

{"v":3,"alg":"ES256","kid":"a1b2c3d4e5f6","ts":1767225600,"cid":"KTR-2026-000123","hld":"Budi Santoso","apr":"Kepala Divisi SDM","exp":"2027-09-09","rsn":"Sah","h":"<sha256 gambar kartu>","sh":"<sha256 file tanda tangan, opsional>","ss":"<tanda tangan ringkas 96×40 terkompresi, opsional>","s":"<tanda tangan, base64url>"}

Tanya jawab singkat

Kenapa ECDSA disarankan, bukan RSA?

Keduanya asimetris dan sama-sama aman untuk SHA-256. Bedanya di panjang tanda tangan: ECDSA P-256 = 64 byte (±86 karakter di QR), RSA-2048 = 256 byte (±343 karakter). Semakin panjang payload, semakin padat modul QR dan semakin sulit dipindai dari kartu berukuran kecil. RSA tetap tersedia bila kebijakan Anda mewajibkannya.

Apakah QR bisa dipindai aplikasi apa pun?

Bisa — isinya teks JSON biasa, jadi pemindai QR apa pun akan menampilkannya. Putusan ASLI/TIDAK ASLI tetap dihitung secara kriptografis di aplikasi ini, bukan dari tampilan teks.

Bisakah file PNG tanda tangan basah disematkan ke QR?

File PNG apa adanya tidak muat (kapasitas maksimum QR ≈ 2.953 byte; PNG tanda tangan biasanya 5–100 KB). Aplikasi menyediakan dua jalur: (1) tanda tangan dicetak sebagai lapisan visual di kartu dan hash SHA-256 file-nya diikat ke payload (field sh) — file tanda tangan diubah → verifikasi gagal; (2) opsi "Sematkan tanda tangan ringkas di dalam QR": gambar dikonversi ke monokrom 96×40 terkompresi (field ss) sehingga verifikator dapat menampilkan ulang tanda tangan langsung dari isi QR dan membandingkannya dengan yang tercetak di kartu.

Kenapa verifikasi tidak butuh gambar kartu lagi?

Sejak skema v2, hash SHA-256 gambar (h) ikut di dalam string yang ditandatangani. Jadi tanda tangan sudah mengikat gambar: memverifikasi tanda tangan dari payload saja cukup untuk menjamin seluruh data (termasuk identitas gambar) asli & tidak diubah. Pencocokan hash dengan file gambar tetap tersedia sebagai opsional lanjutan.

Di perangkat apa verifikasi bisa dilakukan?

Tiga sumber kunci dipercaya otomatis: (1) kunci tertanam di file KartuSign-Verifier.html, (2) kunci penandatangan di perangkat yang sama, (3) riwayat approval perangkat itu. Di luar itu, tempel kunci publik lewat opsi lanjutan. QR yang kid-nya tidak dikenal akan dilaporkan ISSUER TIDAK DIKENAL, bukan asal dinyatakan asli.

Apakah data saya dikirim ke internet?

Ya, ke proyek Supabase Anda sendiri: akun (via Supabase Auth), antrean pengajuan (gambar + data kartu), hasil approval, dan blob kunci privat yang sudah terenkripsi frasa sandi. Proses kriptografi tetap berjalan di browser. Lindani anon key Anda dengan RLS (sudah termasuk di schema.sql) dan jaga kerahasiaan service key Supabase.

Berapa ukuran cetak QR yang aman?

Aturan praktis: modul (kotak terkecil) QR sebaiknya ≥ 0,33 mm saat dicetak. Contoh dengan ECDSA + koreksi galat M (QR versi ±13, 69 modul): 69 × 0,33 mm ≈ 23 mm. Pada kartu ID-1 (85,6 × 54 mm) itu sekitar 27% sisi pendek — jadi atur Ukuran 22–30%. Bila ruang kartu sempit, pilih koreksi galat L atau aktifkan Key ID ringkas agar QR lebih jarang.

Bisa dipakai banyak penerbit / banyak kartu sekaligus?

Untuk batch, gunakan versi backend (Node/Python) dengan kunci di HSM. Versi satu-file ini dirancang untuk penerbitan satuan oleh petugas berwenang.
